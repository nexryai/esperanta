## HTTP forwarding

Send an absolute URL to the proxy. Esperanta connects to the destination, rewrites the request target and forwards the response without caching.

```sh
curl --noproxy '' --proxy http://127.0.0.1:8080 http://example.com/
```

## HTTPS CONNECT

HTTPS clients use the HTTP CONNECT method. The TLS session is established directly with the destination; Esperanta does not terminate or inspect it.

```sh
curl --noproxy '' --proxy http://127.0.0.1:8080 https://example.com/
```

## Upstream headers

For regular HTTP forwarding, top-level `upstream_headers` apply only to the matching destination hostname and replace client values with the same name.

```yaml
upstream_headers:
  "127.0.0.1":
    User-Agent: "Esperanta"
    X-Origin-Authorization: "Bearer secret"
```

Test with dummy values against a local HTTP endpoint that echoes request headers. For this local test, allow port 8000 and disable `deny_private_destinations` in an isolated test instance. Keep production secrets out of shell history and in a configuration file with restricted permissions.

```sh
curl --noproxy '' --proxy http://127.0.0.1:8080 \
  -H 'X-Origin-Authorization: client-value' \
  http://127.0.0.1:8000/debug/headers
```

CONNECT tunnels are opaque. Headers for the TLS client are controlled by the TLS client, not by the proxy.

## Dedicated HTTPS upstream

After [configuring a `request_target`](/en/configuration#fixed-https-forwarding) on port 8081, send a normal HTTP request to that port. Do not use `--proxy` or `--request-target`:

```sh
curl --noproxy '*' 'http://127.0.0.1:8081/api/status?check=1'
```

Esperanta adds the configured headers and connects to the fixed upstream over HTTPS. For Cloudflare Access, allow the configured service token in a Service Auth policy for the application.

## Cloning from a Git mirror

After [configuring a Git mirror](/en/configuration#git-repository-mirror), replace the upstream scheme and host with the local HTTP listener and keep the repository path:

```sh
git clone http://127.0.0.1:8081/nexryai/hoge.git
```

Use the `.git` suffix if the upstream requires it. No forward proxy setting or Cloudflare Access service token is needed on the client. When `read_only: true`, clone and fetch work but pushes are blocked.

## Proxy environment variables

Most command line tools honor standard proxy variables. Restrict them to the current shell rather than exporting them system-wide when only selected commands should use the proxy.

```sh
HTTP_PROXY=http://127.0.0.1:8080 \
HTTPS_PROXY=http://127.0.0.1:8080 \
curl https://example.com/
```

Some tools ignore lowercase variables or have their own proxy settings. Configure the client explicitly when behavior is unclear.
