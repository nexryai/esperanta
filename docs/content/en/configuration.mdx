## Complete example

```yaml
listen: "127.0.0.1:8080"
allowed_sources:
  - "127.0.0.1"
  - "::1"
allowed_ports: [80, 443]
deny_private_destinations: true

upstream_headers:
  api.example.com:
    Authorization: "Bearer domain-secret"

max_concurrent: 1024
max_connections: 2048
max_idle_connections: 1024
max_idle_connections_per_host: 64

dial_timeout: 10s
header_timeout: 10s
request_timeout: 2m
idle_timeout: 90s
tunnel_timeout: 1h
shutdown_timeout: 15s
```

The file is decoded strictly: unknown fields, duplicate fields and multiple YAML documents are rejected. Passing `--check` validates the file without starting the proxy.

## Listener and clients

`listen` must be a literal IPv4 or IPv6 address and a port from 1024 through 65535. An unprivileged process cannot bind privileged ports directly; use a reverse proxy or port redirection if port 80 or 443 is required.

`allowed_sources` accepts individual addresses and CIDR ranges. Connections from other TCP peers are closed before HTTP parsing. The proxy uses the TCP peer address and does not trust `X-Forwarded-For` or similar headers. An empty list is invalid.

## Destinations

`allowed_ports` applies to both regular HTTP forwarding and CONNECT. A destination port that is not listed returns 403.

`deny_private_destinations: true` rejects loopback, private, link-local, shared, documentation, multicast and other non-public destinations. DNS answers containing a mix of public and non-public addresses are rejected as a whole.

## Upstream headers

`upstream_headers` maps an exact destination hostname to headers that Esperanta adds only for that host. There is intentionally no global header option, so credentials cannot be sent to every destination. Matching is case-insensitive and ignores a trailing dot. A configured header replaces any value supplied by the client for the matching request.

```yaml
upstream_headers:
  api.example.com:
    Authorization: "Bearer domain-secret"
```

The following headers are rejected because they are transport metadata: `Host`, `Content-Length`, `Transfer-Encoding`, `Connection`, `Proxy-Connection`, `Proxy-Authorization`, `Keep-Alive`, `TE`, `Trailer` and `Upgrade`. Names must be valid HTTP tokens; values must not contain control characters. Duplicate case-insensitive names are rejected.

CONNECT is an encrypted byte tunnel. Esperanta cannot add HTTP headers inside a TLS session, so `upstream_headers` does not apply to CONNECT traffic.

Matching at the top level does not require HTTPS. Do not put service tokens there if clients can request `http://` for the same host; use a dedicated HTTPS upstream instead.

## Fixed HTTPS forwarding

Each `request_target` entry opens a dedicated HTTP port on the IP address from `listen`. When `type` is omitted, Esperanta forwards to a fixed upstream over HTTPS on port 443. This lets Esperanta add a Cloudflare Access service token without giving it to clients.

```yaml
request_target:
  - port: 8081
    upstream_host: app.example.com
    upstream_headers:
      CF-Access-Client-Id: "<client-id>"
      CF-Access-Client-Secret: "<client-secret>"
```

Use a unique listener port from 1024 to 65535. `upstream_host` accepts a hostname or bare IPv4 or IPv6 address, without a scheme, port, or path. Port 443 must be in `allowed_ports`. Requests preserve the method, path, query, and body. The incoming `Host` cannot change the destination. Absolute URLs, CONNECT, TRACE, and protocol upgrades are rejected.

Per-listener headers replace same-named client headers and are independent of the top-level `upstream_headers`. Omit them or use `upstream_headers: {}` if none are needed. The dedicated ports share `allowed_sources`, destination IP restrictions, and connection and concurrency limits with the forward proxy. Any allowed client can use the service identity through the dedicated port. Keep the config file private and expose the HTTP listener only to trusted clients on a trusted network.

## Git repository mirror

Use `type: git` to forward Git Smart HTTP requests for selected repositories, without storing repositories locally.

```yaml
request_target:
  - port: 8081
    type: git
    upstream_host: 192.168.1.20
    allowed_prefixes:
      - https://git.example.com/nexryai/hoge
      - https://git.example.com/nexryai/fuge
    read_only: true
    upstream_headers:
      CF-Access-Client-Id: "<client-id>"
      CF-Access-Client-Secret: "<client-secret>"
```

`allowed_prefixes` is required. List full HTTPS repository URLs with a common hostname and no port, credentials, query, or fragment. Each entry allows the listed repository with or without the `.git` suffix, not similarly named or nested repositories. The URL hostname sets the upstream `Host` and TLS certificate name; `upstream_host` sets the network destination on port 443. To use the private IP in the example, set `deny_private_destinations: false`, which also relaxes the forward proxy's destination restrictions.

`read_only: true` allows clone and fetch but blocks pushes. If omitted or `false`, pushes are subject to the upstream's permissions. Redirects, Git LFS, and web UI requests are not supported.

## Limits and timeouts

| Option | Behavior |
| --- | --- |
| `max_concurrent` | Combined in-flight HTTP requests and CONNECT tunnels |
| `max_connections` | Accepted client TCP connections, including idle ones |
| `max_idle_connections` | Idle destination connections retained in the pool |
| `max_idle_connections_per_host` | Idle destination connections per host |
| `dial_timeout` | DNS lookup and connection establishment |
| `header_timeout` | Client and destination response headers |
| `request_timeout` | Total duration of a regular HTTP request |
| `idle_timeout` | Idle client and destination connections |
| `tunnel_timeout` | Maximum CONNECT tunnel lifetime, not idle time |
| `shutdown_timeout` | Graceful shutdown deadline |

Values use Go duration syntax such as `10s`, `2m` or `1h`. All durations and limits must be positive.
