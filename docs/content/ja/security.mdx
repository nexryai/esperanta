## 既定の姿勢

サンプル設定はループバックだけで待ち受け、ループバックのクライアントだけを受け入れます。接続元制限とファイアウォールが正しくなるまで、この既定値を維持してください。

`allowed_sources` は主要な認証境界です。ユーザー認証の代わりにはならないため、無制限のプロキシをインターネットへ公開しないでください。任意の公開接続先へ到達できるプロキシは、匿名化や外向きスキャンに悪用されます。

## 接続先の検証

Esperanta は接続前に接続先を解決し、返されたすべてのアドレスをプライベート接続先ポリシーで検査し、検証済みのリテラルアドレスへ接続します。これにより検証と接続の間で二度目の DNS 解決が発生しません。

`deny_private_destinations` が有効な場合、プライベート接続先、非公開レンジ、スコープ付き IPv6 アドレス、公開・非公開が混在する DNS 応答を拒否します。

## Landlock

Linux では Landlock ABI 4 以上が必要です。待ち受けソケットを開いた後にプロセス全体へポリシーを適用します。

- 外向き TCP は `allowed_ports` に限定されます。
- DNS は TCP と、Landlock ABI 10 以上では UDP 53 を使用します。
- リゾルバ設定ファイルは読み取り専用です。
- 書き込み、実行、無関係なファイルアクセスは拒否されます。

Landlock の適用に失敗すると起動も失敗します。サンドボックスなしへのフォールバックはありません。

## systemd

インストールされるユニットは `DynamicUser=yes`、空のケーパビリティセット、`NoNewPrivileges=yes` を使用します。さらに読み取り専用システム、プライベート tmp / devices、プロセスとカーネルの保護、システムコール許可リスト、書き込み可能実行メモリの禁止を有効にします。

稼働中の実効サンドボックスを確認できます。

```sh
systemd-analyze security esperanta.service
```

## Snap

Snap は strict confinement を使い、起動前に非特権 ID へ切り替えます。Snap サンドボックス内でも Landlock は有効です。Snap が持つインターフェースは `network` と `network-bind` だけです。

## ログと秘密情報

プロキシはリクエストボディや設定したヘッダー値をログへ出しません。認証ヘッダーを含む `/etc/esperanta/config.yaml` は秘密情報として扱い、パーミッションを制限してください。
