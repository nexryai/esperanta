## HTTP 転送

プロキシへ絶対 URL を送ります。Esperanta は接続先へ接続し、リクエストターゲットを書き換え、レスポンスをキャッシュせずに転送します。

```sh
curl --noproxy '' --proxy http://127.0.0.1:8080 http://example.com/
```

## HTTPS CONNECT

HTTPS クライアントは HTTP CONNECT メソッドを使います。TLS セッションは接続先と直接確立され、Esperanta は終端も検査もしません。

```sh
curl --noproxy '' --proxy http://127.0.0.1:8080 https://example.com/
```

## 上流ヘッダー

通常の HTTP 転送では、トップレベルの `upstream_headers` は接続先ホスト名が一致する場合だけ適用され、クライアントの同名ヘッダーを置き換えます。

```yaml
upstream_headers:
  "127.0.0.1":
    User-Agent: "Esperanta"
    X-Origin-Authorization: "Bearer secret"
```

ダミーの値を使い、リクエストヘッダーを返すローカル HTTP エンドポイントで結果を確認できます。この例では、隔離したテスト用インスタンスでポート 8000 を許可し、`deny_private_destinations` を無効にします。本番の秘密情報はシェルの履歴に残さず、アクセス権を制限した設定ファイルに保存してください。

```sh
curl --noproxy '' --proxy http://127.0.0.1:8080 \
  -H 'X-Origin-Authorization: client-value' \
  http://127.0.0.1:8000/debug/headers
```

CONNECT トンネルは不透明です。TLS クライアント用のヘッダーはプロキシではなく TLS クライアントが制御します。

## 専用ポートからの HTTPS 転送

8081 に [`request_target` を設定](/ja/configuration)したら、そのポートに通常の HTTP リクエストを送ります。`--proxy` や `--request-target` は不要です。

```sh
curl --noproxy '*' 'http://127.0.0.1:8081/api/status?check=1'
```

Esperanta は設定済みのヘッダーを付け、固定の上流に HTTPS で接続します。Cloudflare Access を使う場合は、対象アプリケーションの Service Auth ポリシーでサービストークンを許可してください。

## Git ミラーからの clone

[Git ミラーを設定](/ja/configuration)したら、上流 URL のスキームとホストをローカルの HTTP 待ち受け先に置き換え、リポジトリのパスはそのまま使います。

```sh
git clone http://127.0.0.1:8081/nexryai/hoge.git
```

上流が必要とする場合は `.git` を付けます。クライアント側にフォワードプロキシの設定や Cloudflare Access のサービストークンは不要です。`read_only: true` では clone と fetch ができ、push は拒否されます。

## プロキシ環境変数

多くのコマンドラインツールは標準のプロキシ変数を参照します。一部のコマンドだけプロキシを使う場合は、システム全体に export せず現在のシェルに限定します。

```sh
HTTP_PROXY=http://127.0.0.1:8080 \
HTTPS_PROXY=http://127.0.0.1:8080 \
curl https://example.com/
```

ツールによっては小文字の変数を無視したり、独自のプロキシ設定を持ったりします。動作が不明な場合はクライアントを明示的に設定してください。
